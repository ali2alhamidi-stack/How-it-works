# موافقة العميل على التصميم — دورة قبل الطباعة والقص

هذا القسم **إضافة إلى النظام القائم** وليس نظاما منفصلا، ويستخدم قاعدة بيانات المنشأة وصلاحيات فروعها وسجلها.

## التشغيل

1. افتح `/proof-center.html` وأنت مسجل بحساب المالك أو المدير المخول بإدارة أوامر العمل.
2. أنشئ أمر العمل وارفع صورة النسخة النهائية للتصميم؛ يشترط أن يكون الأمر في حالة **مسودة** أو **اعتماد**.
3. اختر الأمر واضغط **إنشاء رابط المراجعة** ثم انسخه إلى العميل. الرابط يستعمل رمزا عشوائيا قويا، ولا يحوي معلومات أسعار أو تكاليف.
4. يفتح العميل `/proof.html?token=...` دون إنشاء حساب. تعرض الصفحة رقم الأمر والعنوان والصورة والمقاس والكمية ورقم الإصدار.
5. يختار **أوافق على التصميم**، أو **أطلب تعديلا** مع ملاحظة إلزامية. يحفظ الرد مرة واحدة في تاريخ الإصدار.
6. عند طلب التعديل يحدث المصمم صورة الأمر أو التفاصيل عبر شاشة أمر العمل ويصدر رابطا جديدا. لا يقبل الرابط السابق أي مراجعة.
7. لا يسمح الخادم بالانتقال إلى مرحلة **جاهز للتنفيذ** أو **قيد التنفيذ** بعد طلب موافقة العميل إلا إذا كان أحدث رد `approved`، مع استمرار شرط **اعتماد التصميم الداخلي**.

## قواعد الأمان والتوثيق

- يصدر الرابط موظف مخول فقط، مع حماية الجلسة وCSRF. موظف لا يملك إدارة الأوامر لا يمكنه إصدار الرابط ولا يظهر له رمز الاعتماد في بيانات الخادم.
- تنتهي الروابط بعد إلغاء الأمر أو بدء الإنتاج أو تغيير التصميم وإصدار نسخة أحدث.
- كل رد يسجل تاريخا ورقم إصدار واسم العميل إن قدمه وتعليقه وحالة القرار في `order.proofHistory`، بحد أقصى 50 قرارا تاريخيا.
- لا تستطيع صفحة العميل تعديل معلومات أمر العمل أو تسعيره؛ ينحصر طلب POST في قرار محدد وملاحظة.
- تعديل التصميم المعتمد بعد بدء الإنتاج يرفض حتى يعاد تنظيم أمر التشغيل أو ينشأ أمر تصحيح.
- تحفظ الردود عبر معاملة SQLite، وتزداد مراجعة المنشأة، لذلك يحتاج الموظف إلى تحديث بيانات النظام قبل متابعة الخطوات.
- هذا رابط خاص موجه إلى العميل المقصود؛ من يملك الرابط يمكنه رؤية التصميم واتخاذ القرار مرة واحدة، لذا لا تنشره في إعلان عام.

## واجهات API

- `POST /api/orders/:orderId/proof` — حساب مخول، JSON `{"force":false}`، يولد الرابط أو يعيده؛ `force:true` يبطل الرابط السابق ويصدر رابطا جديدا.
- `GET /api/public/proofs/:token` — يرد بمعلومات التصميم اللازمة للموافقة فقط.
- `POST /api/public/proofs/:token` — JSON `{"revision":1,"decision":"approved","name":"","comment":""}` أو `changes_requested` مع تعليق.
- `GET /api/state` — الحالة والتعليق متاحان للإدارة المخولة حسب حدود الفرع.

## حدود المرحلة

- المركز حاليا **صفحة إدارية إضافية** على نفس النطاق، ولم يدمج بعد ضمن شريط أقسام التطبيق الأساسي.
- يعرض تصميم صور PNG/JPEG/WebP المرفوعة كنص data URL وفق سياسة النظام الحالي، ولا ينشئ ملف قص أو طباعة تلقائيا.
- يحتاج استلام الرد من خارج جهاز المنشأة إلى تشغيل الخادم عبر HTTPS.
- لا تعتبر موافقة العميل فحص جودة، ولا تضمن تطابق الألوان المطبوعة مع الشاشة.
