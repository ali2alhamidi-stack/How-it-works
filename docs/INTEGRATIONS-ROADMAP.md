# واتساب والتنبيهات والاشتراكات

## الحالة الحالية

يدعم مالك المنصة إدارة المنشآت وحدود الفروع والمستخدمين وتاريخ انتهاء الاشتراك. هذه إدارة اشتراك تشغيلية **وليست بوابة دفع أو تحصيل تلقائي**. لم نُفعّل أي رسالة WhatsApp حقيقية لعدم توفر حساب Meta Business وPhone Number ID ورمز وصول وقالب موافق عليه وموافقات المستخدمين.

أضفنا محول `server/whatsapp-cloud.cjs` الذي لا يرسل افتراضيا. يتطلب إرسال قالب من نوع Utility تحقق موافقة صريحة مسجلة `consentAt`، رقم E.164، اسم قالب مصرح به، الإعدادات `WHATSAPP_ACCESS_TOKEN` و`WHATSAPP_PHONE_NUMBER_ID` و`WHATSAPP_GRAPH_VERSION`، وتمرير الخيار `send:true`. الاتصال يذهب حصرا إلى واجهة Meta عبر HTTPS. بيانات الوصول لا تدخل Git ولا تُطبع في الأخطاء.

## التنبيهات الممكنة بعد الربط

- تنبيه مالك المؤسسة بقرب انتهاء الاشتراك بعد موافقته، وفق القوالب المعتمدة.
- تنبيه مسؤول العمل بطلب معتمد أو تأخر أمر عمل.
- إرسال رابط مراجعة تصميم إلى العميل الذي وافق على تلقي رسائل الخدمة.

لا ترسل الرسائل غير التسويقية إلا ضمن سياسات WhatsApp Business المعمول بها وبحسب موافقة المتلقي. تحتاج قوالب الإشعارات الصادرة خارج نافذة خدمة العميل إلى موافقة Meta، وقد تُحتسب رسوم لكل رسالة وفق بلد المستلم وفئة القالب.

**المهم:** لم نضف بعد آلية طلبات إرسال مؤجلة (outbox) مع retries وwebhooks لحالة التسليم. لا تربط استدعاء واتساب مباشرة بحفظ أمر العمل قبل تجهيز الطابور الموثوق ومنع التكرار؛ وإلا قد تُرسل الرسالة رغم فشل العملية. لا تعتبر رد HTTP نجاحا للتسليم النهائي.

## الخطوات المطلوبة من مالك النظام

1. تجهيز حساب WhatsApp Business Platform وربط رقم الأعمال والحصول على رمز وصول آمن.
2. إنشاء قوالب Utility بالعربية والموافقة عليها.
3. ضبط سياسة موافقة المستخدم ونموذج حفظ الدليل `consentAt` وسياسة إلغاء الموافقة.
4. تفعيل خدمة الإرسال وطابور الرسائل وwebhook والحماية وإعادة الإرسال المنضبطة، ثم اختبارات إرسال حقيقية.
5. اختيار طريقة الدفع والباقات والضرائب أو الفواتير الخاصة بمالك المنصة بشكل مستقل؛ النظام نفسه ليس برنامجا محاسبيا.

لم تُرسل أي رسالة أو تُنشأ اشتراكات مدفوعة في هذه المرحلة.
