# دليل البنية والتكامل اللاحق

تاريخ المراجعة: 2026-11-13. هذه وثيقة تسليم وخطة تكامل مقترحة. نقاط API والجداول والخدمات أدناه ليست خادما منفذا في النسخة الحالية.

## النسخة الحالية

واجهة عربية RTL تعمل من ملف HTML مستقل بعد البناء، بواجهات سطح مكتب وهاتف. `build.py` يضم الشيفرة والأصول في `index.html`. لا يحتاج التشغيل العادي إلى تنزيل مكتبات أو اتصال بخادم. ملفات المصدر منفصلة لتسهيل التطوير والمراجعة اللاحقة:

| الجزء | المسؤولية الحالية |
|---|---|
| `src/app.js` | التوجيه عبر hash، العرض، النماذج، الأحداث والطباعة والحفظ المحلي |
| `src/model.js` / `WOModel` | قواعد حالات الأوامر، الصلاحيات المحلية، المخزون والحصص والأداء والتحقق من النسخ |
| `src/calculators.js` / `WOCalc` | حسابات نقية للمقاسات والخامة والتكلفة وLED |
| `src/catalog.js` / `WOCatalog` | فئات الخدمات والأيقونات والمراحل والصلاحيات |
| `src/qr.js` / `WOQR` | توليد QR داخل المتصفح بلا خدمة خارجية |
| `assets/` | أصول الهوية والتصميم المضمنة عند البناء |
| `tests/` | اختبارات Node لمنطق النموذج والحاسبات وQR |

الحالة الحالية `schemaVersion:1` كائن واحد يضم الهوية والفروع والمستخدمين والعملاء والأوامر والخامات والبواقي والمشتريات والتقييمات والسجل والمسودات والإعدادات. مفتاح البيانات `artplus.workorders.v1` ومفتاح اختيار حساب العرض والفرع والمظهر `artplus.session.v1` في `localStorage`. النطاق هو المتصفح وموضع فتح الصفحة؛ حفظ الملف في مكان آخر أو فتحه في متصفح آخر لا يعد مزامنة.

اختيار الإدارة أو الموظف تجربة صلاحيات داخل الجهاز، وليس إثبات هوية أو حماية من مستخدم يمكنه تعديل JavaScript أو التخزين. الصور الحالية Data URLs محلية. النسخ الاحتياطية JSON، وتصدير القوائم والتقارير CSV، والطباعة من المتصفح. إضافة عنوان API أو رابط عام في الإعدادات تحفظ الإعداد فقط؛ لا تشغل طلبات شبكة أو استقبالا مركزيا.

## تجهيز المصدر لـ GitHub

الخطوة اللاحقة هي إنشاء مستودع مصدر بإذن النشر المناسب، يضم `src/` و`assets/` و`docs/` و`tests/` و`build.py` و`package.json` وملفات التراخيص. لا يعد وجود هذه البنية رفعا إلى GitHub، ولم ينشأ مستودع بعيد بهذه الوثيقة. قبل النشر يجب أن تكون بيانات المثال بلا معلومات عملاء فعلية، وأن تستبعد النسخ JSON والصور التشغيلية والمفاتيح السرية وملفات البيئة.

يوصى بأن يعيد CI تشغيل `node --test` و`python build.py` ويتحقق من الناتج، مع إصدار مرقم للملف المستقل وإبقاء المصدر مرجع التطوير. مفاتيح WhatsApp أو التخزين أو جلسات الخادم لا توضع في HTML أو المستودع. واجهة حسابات الإنتاج تبقى قابلة لإعادة الاستخدام والاختبار على الخادم عند الحاجة، مع إعادة التحقق من أي عرض سعر يعتمد عليه العمل.

## حدود المؤسسات والفروع والمصادقة

الخادم المستقبلي مصدر الحقيقة. يقترح إضافة `tenantId` لكل سجل تشغيلي، وربط المستخدم بعضوية المؤسسة والفروع والصلاحيات. تحتوي الجداول الأساسية على `id, tenant_id, branch_id` حيث يلزم، و`created_at, updated_at, version`. المؤسسة ليست موجودة حاليا كطبقة عزل في نسخة العرض، وتحتاج هجرة صريحة من الإصدار الأول.

يستمد الخادم الهوية والمؤسسة والصلاحيات من جلسة موثقة، ويطابقها مع المؤسسة في المسار والفرع المطلوب. كل قراءة وكتابة وملف وتصدير وتقرير يعاد فحصه في الخادم. إخفاء زر في المتصفح أو إرسال `userId` لا يمنح صلاحية. موظف الإنتاج يقرأ أعماله المصرح بها ويسجل إنجاز تكليفه فقط؛ إظهار الأرقام المالية صلاحية مستقلة. يراعى عزل الاستعلامات بالمؤسسة ثم الفرع، مع سياسة للمدير متعدد الفروع.

## عقد API مقترح

بادئة التشغيل `/v1/tenants/{tenantId}`؛ الجدول أدناه تصميم للتنفيذ التالي. أسماء الحقول يمكن مواءمتها مع العقد الحالي، لكن الخادم يولد أرقام الأوامر والطوابع الزمنية وهوية المنفذ وسجل التدقيق. تعرض الأخطاء برسالة عربية مع رمز ثابت و`requestId`، وتستخدم صفحات محدودة للقوائم.

| الوظيفة | نقطة مقترحة | قيد الخادم الأساسي |
|---|---|---|
| الدخول والجلسة | `POST /v1/auth/sessions`, `GET /v1/auth/me`, `DELETE /v1/auth/session` | مصادقة فعلية، جلسات آمنة، إلغاء الجلسة |
| المؤسسات والعضويات | `GET /v1/tenants`, `GET /members`, `PATCH /members/{id}` | إدارة العضويات والتفويض داخل المؤسسة |
| الفروع | `GET/POST /branches`, `PATCH /branches/{id}` | فروع المؤسسة والصلاحية الإدارية |
| الهوية والإعدادات | `GET/PATCH /settings` | صلاحية إدارة الإعدادات والتحقق من القيم |
| العملاء | `GET/POST /clients`, `PATCH /clients/{id}` | مؤسسة وفرع مصرح بهما |
| الأوامر | `GET/POST /orders`, `GET/PATCH /orders/{id}` | منع تعديل الأمر المسلم، وقفل تفاؤلي للنسخة |
| المراحل | `POST /orders/{id}/transitions` | انتقال مسموح واعتماد التصميم والجودة واكتمال الفريق |
| اعتماد التصميم | `POST /orders/{id}/design-approval` | هوية المعتمد ونسخة التصميم المعتمدة |
| فحص الجودة | `POST /orders/{id}/quality-checks` | مسؤول مخول ونتيجة موثقة |
| الفريق والحصص | `PUT /orders/{id}/assignments` | فروع صحيحة، حصص مجموعها 100%، بلا تكرار |
| إنجاز الموظف | `POST /orders/{id}/assignments/{id}/complete` | منفذ التكليف نفسه، مرة واحدة، وقت معتمد |
| الملاحظات | `POST /orders/{id}/notes` | صلاحية مشاهدة ومساهمة في الأمر |
| الخامات | `GET/POST /materials`, `PATCH /materials/{id}` | وحدة ومخزون وفرع صحيح؛ الحركات بسجل منفصل |
| صرف الخامة | `POST /orders/{id}/consumptions` | خصم ذري، هدر جزء من المصروف، منع المخزون السالب |
| البواقي | `GET/POST /remnants` | خامة ومقاس وسماكة وموقع ومصدر موثق |
| حجز الباقي | `POST /remnants/{id}/reservations`, `DELETE /remnants/{id}/reservation` | حجز نشط واحد، توافق الأمر والخامة والمقاس، صلاحية تحريره |
| المشتريات | `GET/POST /purchases`, `POST /purchases/{id}/approve`, `POST /purchases/{id}/reject` | مراحل وصلاحيات المؤسسة والفرع |
| الاستلام | `POST /purchases/{id}/receipts` | استلام لا يكرر زيادة المخزون ولا التكلفة |
| مراجعات الإدارة | `GET /reviews`, `POST /orders/{id}/review-invitations` | أمر مسلم ورابط مخصص ومشاهدة للإدارة المخولة |
| تقييم بلا حساب | `GET/POST /v1/public/reviews/{token}` | رمز عشوائي خاص بأمر واحد، معلومات عامة محدودة ومكافحة إساءة |
| رفع الملفات | `POST /media/uploads`, `POST /media/{id}/finalize` | امتلاك الأمر، نوع وحجم وفحص الملف قبل الإتاحة |
| ربط الملف بالأمر | `POST /orders/{id}/attachments` | معرف ملف دائم داخل المؤسسة نفسها |
| الأداء والتقارير | `GET /reports/operations`, `GET /reports/financials`, `GET /members/{id}/performance` | نطاق الفروع والفترة وصلاحية المالية |
| التدقيق | `GET /audit-events` | سجل غير قابل لتعديل العميل، وأذونات مشاهدة مستقلة |
| التنبيهات | `GET /notifications`, `POST /notification-subscriptions` | المستلم والمحتوى ضمن نطاق صلاحياته |
| قنوات الإرسال | `POST /notification-jobs`, `POST /v1/webhooks/notifications/{provider}` | قنوات مصرح بها وتحقق من إشعار المزود ومنع التكرار |

كل مسار مختصر في الجدول يستخدم بادئة المؤسسة المذكورة، باستثناء مسارات `/v1/auth` و`/v1/public` و`/v1/webhooks` الصريحة. API لا يقبل بيانات مالية أو `tenantId` من العميل باعتبارها موثوقة بمجرد وصولها.

## المعاملات ومنع التكرار

يقترح `Idempotency-Key` للعمليات ذات الأثر، مرتبط بالمؤسسة والمنفذ ونوع العملية وبصمة الحمولة. إعادة الطلب نفسه تعيد النتيجة نفسها؛ استعمال المفتاح بحمولة مختلفة يرفض بتعارض. يحفظ المفتاح والنتيجة في المعاملة نفسها مع الأثر التشغيلي، مع قيود فريدة على معرفات الإيصالات والحركات.

- استلام الشراء يحدث إيصالا وحركة مخزون وحساب تكلفة الوحدة الموزونة وتغيير المرحلة وسجل التدقيق في معاملة واحدة. لا يكفي تعطيل زر الاستلام؛ تكرار أو تزامن الطلبين يجب أن ينتج زيادة واحدة.
- حجز الباقي يستخدم قيدا فريدا للحجز النشط وقفل السجل أو تحديثا شرطيا لنسخته. يفشل الطلب الثاني عند التنافس؛ الإلغاء يحرر الحجز ضمن المعاملة، والتسليم يثبت الاستخدام وفق السياسة.
- صرف الخامة يقفل رصيدها ويمنع السالب، ويسجل الكمية الكلية والهدر منها وتكلفة الحركة وقت الصرف. الطلب المعاد لا يضيف تكلفة إلى الأمر مرة ثانية.
- تغيير المرحلة يتحقق من الحالة الحالية واعتماد التصميم والفريق والجودة في الخادم. تعديل قديم يرسل `version` أو `If-Match`؛ يتلقى تعارضا بدلا من الكتابة فوق تعديل أحدث.

## الصور والملفات

تستبدل Data URLs بمعرفات ملفات وروابط وصول مستقرة. يسجل الخادم الملف ومالكه ونوعه وحجمه وبصمته، ويصدر رابط رفع مؤقتا محدود الصلاحية، ثم يثبت الرفع بعد التحقق. يحفظ الأمر `mediaId` وبيانات الملف؛ يمكن أن يكون رابط التحميل موقعا وقصير الأجل لكن معرف الملف وسجل ملكيته دائمين. لا تخزن روابط الرفع المؤقتة باعتبارها رابط التصميم النهائي. يضبط الوصول للتصاميم على المؤسسة والأمر، ويتحقق من نوع الملف وحجمه ومحتواه، مع نسخ احتياطي للملفات وقاعدة البيانات معا.

## التقييمات بلا حساب

ينشأ الرمز العام على الخادم بعد التسليم بعشوائية تشفيرية كافية، مع تخزين بصمته وربطه بأمر ومؤسسة وفرع؛ لا تستبدل هذه الطبقة بمعرفات العرض المحلية. الصفحة العامة لا تكشف التكلفة أو الفريق أو بيانات العميل الخاصة. يحكم الخادم تاريخ الصلاحية والإلغاء وإرسال تقييم واحد لكل دعوة، ويعامل إعادة الإرسال بنفس المفتاح كطلب مكرر. يطبق حدود الطلبات على الرمز والمصدر مع حدود الاسم والتعليق والتقييم 1..5، وترميز النص عند العرض. تظهر رسالة أن التقييم يصل للإدارة ومدير الفرع، ولا ينشر للعامة.

## التنبيهات وWhatsApp والمزامنة

لا يوجد إرسال WhatsApp آلي في النسخة الحالية؛ زر نسخ تقرير التشغيل يجهز نصا فقط. التنفيذ التالي يحتاج مزود قناة وإعدادات مؤسسة وقوالب وموافقات مناسبة، مع أسرار على الخادم. لا تنشئ الواجهة اتصالا مباشرا بمفتاح المزود.

يقترح transactional outbox: داخل معاملة التسليم مثلا يحفظ الخادم حالة الأمر وحدثا مثل `order.delivered` ومهمة إرسال. عامل مستقل يقرأ الأحداث بعد نجاح المعاملة، ويرسل بمفتاح منع تكرار، ويسجل المحاولات ونتيجة المزود ويعيد المحاولة بتأخير. إشعارات المزود تتحقق ثم تعالج مرة واحدة. فشل الرسالة لا يرجع حالة الأمر ولا يعلن نجاح إرسال غير مؤكد.

المزامنة المركزية تبدأ بقراءة وكتابة API مع رقم نسخة. إذا أضيف العمل دون اتصال لاحقا، يحتاج طابور أوامر محليا ومعرفات عمليات وحل تعارضات ظاهر للمستخدم. الحجوزات والأرصدة أثناء انقطاع الاتصال تكون طلبات معلقة حتى يعتمدها الخادم؛ لا يمكن ضمان حجز قطعة واحدة عالميا بواسطة `localStorage` لأجهزة منفصلة.

## Windows وAndroid

لا توجد حزمة Windows أصلية أو APK أو توقيع متجر في هذا التسليم. الواجهة المتجاوبة أساس للتجربة على المتصفح. التغليف اللاحق يحتاج قرار تقنية، إدارة تحديثات وتوقيع وأذونات ورفع ملفات وطباعة وتخزين آمن للجلسات واختبار أجهزة؛ ولا يحل وحده المصادقة أو مزامنة البيانات. لا تتضمن الوثيقة اختيار إطار أو ادعاء أن التثبيت جاهز.
