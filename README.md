# نظام أوامر العمل والتشغيل

منصة عربية لإدارة نشاط الدعاية والإعلان والطباعة، من استلام الطلب إلى تسليمه ومتابعة خاماته وتكلفته وفريقه. **تطبيق واحد** للمالك والمدير والموظف والمشتريات، مع لوحة مستقلة لمالك المنصة لإنشاء المنشآت وحساباتها.

الإصدار **2.0.0** يضم واجهة RTL متجاوبة، خادما مركزيا بـNode.js وقاعدة SQLite، ونسخة عرض محلية مستقلة. المصدر في [How-it-works](https://github.com/ali2alhamidi-stack/How-it-works). حسابات التشغيل والبيانات تحفظ في الخادم؛ GitHub مستودع للمصدر والفحص الآلي، وتشغيل النظام المركزي يحتاج خادم Node.js مع تخزين دائم وHTTPS.

## ما يشمله النظام

| القسم | الوظائف |
|---|---|
| مالك المنصة | إنشاء منشآت وحساب مالك لكل منشأة، حدود المستخدمين والفروع، الحالة وتاريخ الانتهاء وسجل الإجراءات. |
| الفروع والصلاحيات | فصل المنشآت والفروع على الخادم، وأدوار وصلاحيات تحدد الأقسام والعمليات والأسعار المتاحة لكل مستخدم. |
| أوامر العمل | مسودة، اعتماد تصميم، انتظار، تنفيذ، جودة، جاهزية وتسليم؛ صور وملاحظات ومقاسات وأولوية ومواعيد. |
| الفريق والأداء | توزيع المهمة بين عدة موظفين بحصص مجموعها 100%، استلام وإتمام مستقلان، وقت مخطط وفعلي، ومؤشرات شهرية موزونة. |
| الخامات والمخزون | SKU وباركود ووحدة رصيد وعبوات تحويل ومقاس وسماكة وGSM ومورد وموقع؛ حجز وصرف وهدر وجرد وتحويل وبواقي. |
| المشتريات | طلب ثم اعتماد ثم استلام؛ تحويل العبوات إلى وحدة الرصيد وتحديث متوسط التكلفة مرة واحدة. |
| الحاسبات | ألواح وأكريلك، ورق وداي كت، رول وأحبار، حروف وشعارات، LED وترانسات، وتكلفة دفعة؛ نقل الناتج إلى مسودة أمر. |
| التقارير | بيع وتكلفة تشغيل مباشرة وهامش مساهمة للأوامر المسلمة، دون محاسبة أو ضريبة. |
| تقييم العميل | رابط وQR لأمر مسلم؛ تقييم واحد واسم اختياري دون تسجيل دخول، مع ظهور التعليق للإدارة المخولة. |
| الهوية والتطبيق | اسم وشعار وألوان وكليشة، مظهر فاتح/داكن، وأيقونات ملونة؛ PWA قابل للتثبيت من المتصفح على الأجهزة المدعومة. |

يتضمن دليل الخامات **28 قالبا في 11 عائلة** مبنية على مراجع مصانع. القوالب تبدأ بصفر رصيد وصفر تكلفة، وتحتاج تأكيد بيانات المورد. تشمل الخدمات الطباعة الورقية والبنرات واللوحات والأختام والهدايا والمجسمات ومشاريع التخرج.

## التشغيل المحلي السريع

يلزم **Node.js 24.22 أو أحدث ضمن الإصدار 24**. لا توجد حزم npm مطلوبة للتشغيل؛ الواجهة المبنية موجودة في `public/`.

```sh
git clone https://github.com/ali2alhamidi-stack/How-it-works.git
cd How-it-works
node scripts/dev.cjs
```

افتح **http://127.0.0.1:4173/**. ينشئ هذا الأمر قاعدة تجربة منفصلة في `data/development.sqlite`، ويحافظ على تعديلاتك عند إعادة التشغيل.

| الحساب التجريبي | البريد | كلمة المرور |
|---|---|---|
| مالك المنصة | platform@demo.local | PlatformDemo!2026 |
| مالك المنشأة | owner@demo.local | ArtPlusDemo!2026 |
| مدير الفرع | manager1@demo.local | ArtPlusDemo!2026 |
| موظف | emp1@demo.local | ArtPlusDemo!2026 |
| المشتريات | buyer@demo.local | ArtPlusDemo!2026 |

**حسابات الجدول للتجربة المحلية فقط.** تشغيل الإنتاج لا ينشئ حسابات أو بيانات افتراضية. استخدم لوحة مالك المنصة لإنشاء منشأة جديدة فارغة، ثم ادخل بحساب مالكها لإضافة الفروع والمستخدمين والخامات.

## البناء والتحقق

Python 3 مطلوب لإعادة بناء الواجهة، ويستخدم المكتبة القياسية فقط:

```sh
python3 build.py
node scripts/verify-build.cjs
node --test tests/*.test.cjs
```

ينتج البناء:

- `public/`: واجهة النظام المركزي وملفات PWA، يقدمها خادم التطبيق.
- `index.html` في جذر المشروع: عرض محلي مستقل يمكن فتحه دون خادم، ببيانات توضيحية محلية. يولد من المصدر ولا يتصل بحسابات النظام المركزي.

يشغل مسار [GitHub Actions](https://github.com/ali2alhamidi-stack/How-it-works/actions) الاختبارات والبناء والتحقق من الملفات، ويتحقق أن `public/` يطابق المصدر، ثم يتيح ملفات الواجهة والعرض في مرفق البناء. لا ينشر هذا المسار خادما أو قاعدة بيانات.

## البيانات والمزامنة

الخادم هو مرجع الحسابات والصلاحيات والأرصدة. تحفظ المسودات والطلبات المؤجلة على الجهاز في IndexedDB، وتبقى العملية غير معتمدة حتى تأكيد الخادم. عند التعارض يحتفظ النظام بالطلب للمراجعة ويعرض البيانات المؤكدة. إعادة إرسال الطلب نفسه لا تكرر خصم المخزون أو استلام المشتريات.

يسمح الحساب بتبويب تحرير واحد في المتصفح نفسه باستخدام Web Locks؛ التبويبات الأخرى للقراءة. عند إغلاق الكاتب يمكن تحديث التبويب الآخر لاستلام التحرير واسترجاع أحدث الطلبات المحفوظة. المتصفح الذي لا يدعم القفل يفتح للقراءة حفاظا على العمليات. حسابات مختلفة وأجهزة مختلفة تخضع أيضا للتحقق من مراجعة البيانات على الخادم.

## تشغيل الإنتاج

راجع [دليل الخادم](server/README.md) لإنشاء أول مالك بكلمة مرور من stdin، وضبط عنوان التطبيق والجلسات، وأخذ نسخة SQLite متسقة واستعادتها. لا تدخل قاعدة البيانات أو ملفات البيئة أو كلمات مرور الإنتاج في Git.

يتوفر [قالب تشغيل Docker وCaddy](deploy/OPERATIONS.md) بخادم واحد، HTTPS، تخزين دائم ونسخ احتياطي موضح. القالب جهز وراجع نصيا؛ **لم يبن أو يشغل على مضيف إنتاج في هذه الجولة**. يلزم التحقق من المضيف والنطاق والتخزين والاستعادة قبل استقبال بيانات العمل الفعلية.

## الحدود الموضحة

- نسخة Windows وAndroid الحالية **PWA من المتصفح**؛ لا تتضمن APK أو EXE، ولم يختبر التثبيت على جهاز فعلي.
- المتاح لواتساب تجهيز التقرير ونسخه. الإرسال الآلي يحتاج ربط WhatsApp Business وإعداد الخادم.
- توزيع القص شبكة تقديرية، وليس ملف ماكينة أو تحسين قص للأشكال غير المنتظمة. حسابات LED والترانسات تحتاج مراجعة مواصفات المنتج والفني.
- بيانات الجهاز ليست بديلا عن نسخة الخادم، والجهاز المشترك يحتاج إدارة وصول مناسبة. أول دخول يحتاج الاتصال.
- لم يجر اختبار تحميل مرتفع أو تشغيل متعدد الخوادم؛ التصميم الحالي خادم Node واحد وقاعدة SQLite محلية دائمة.

## اعتماد التصاميم من العميل

افتح **`/proof-center.html`** بعد تسجيل الدخول بحساب مالك المنشأة أو المدير. اختر أمر عمل في مرحلة المسودة أو اعتماد التصميم يحتوي على صورة، وأنشئ رابطا مستقلا. يفتح العميل **`/proof.html?token=...`** على جواله دون تسجيل دخول، ويراجع التصميم والمقاسات والكمية ويختار **الموافقة** أو **طلب تعديل** مع ملاحظة إلزامية عند طلب التعديل.

يحفظ الخادم قرار العميل وإصدار التصميم في سجل أمر العمل ويمنع بدء الإنتاج إذا كانت موافقة العميل مطلوبة ولم تسجل على أحدث إصدار. عند تغيير التصميم أو المقاسات يلغى الرابط القديم ويصبح إصدار رابط جديد إلزاميا. موافقة العميل لا تلغي اعتماد المدير الداخلي أو فحص الجودة. أرسل الرابط فقط إلى العميل المقصود.

هذه بوابة إدارية إضافية على **نفس الخادم والمستودع** وليست بعد تبويبا في القائمة الرئيسية؛ تبقى الأقسام السابقة دون حذف. تحتاج البوابة الخادم المركزي وHTTPS، ولا تعمل من ملف العرض المحلي.
